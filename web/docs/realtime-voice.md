# Real-time voice conversation

In progress. A player explicitly starts and stops a microphone session. Browser WebRTC sends and receives real-time audio through OpenAI; no raw audio is persisted by this app. User and assistant transcription events are shown in memory. An utterance only becomes a game command after explicit review through the existing intent/confirmation path. Existing typed and recorded inputs remain available.

The local authenticated server exchanges browser SDP with OpenAI using `gpt-realtime-2.1`; the permanent API key never goes to the browser. It owns an opaque session ID, rejects duplicate/concurrent sessions, and attempts provider hangup at stop or after 60 seconds. The client also stops tracks and closes the peer on stop, hidden tab, page exit and cleanup. Local timer hangup is best effort: process termination can interrupt it. Hosted mode remains disabled until enforceable server-side time/cost bounds are verified; a client timer or session-count limit alone is insufficient.

The client transport forwards only transcription events to UI callbacks and ignores provider tool/function events. A separate UI confirmation and existing game APIs remain responsible for all mutations. Failed hangups retain the local session for retry; the server timer retries while its process is alive.

Verification so far: model metadata GET returned HTTP 200. Six focused mock-provider/media tests passed for owner scoping, stop, hosted denial, hangup failure/retry, transcript events, ignored tool events and microphone permission arriving after stop; typecheck passed. Real Chrome WebRTC with synthetic speech reached OpenAI, emitted speech-start, speech-stop, input-transcript completed, output-audio-transcript done and response-done events, then successfully hung up. A very quiet continuous background was needed after the synthetic recording so that VAD received audio after playback stopped. OpenAI returned an `rtc_` call ID, and validation was corrected to accept it. No actual microphone, answer-content quality, integrated game UI or hosted duration enforcement has been verified.

Sources: [Realtime WebRTC](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime), [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations), [Realtime calls hangup](https://developers.openai.com/api/reference/resources/realtime/subresources/calls/methods/hangup).
