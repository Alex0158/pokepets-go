# Battle Auto mode

Alex / Codex — in progress. An Auto command selects exactly one legal action on the player's current turn in an existing face-to-face or practice match. The target UI defaults Auto on and allows switching it off. The opponent is never controlled by this mode; the practice bot remains the separate deterministic opponent. Repeating Auto is a client choice, not an unattended server loop.

OpenAI's [Decisions guide](https://developers.openai.com/api/docs/guides/decisions) specifies POST /v1/decisions, `gpt-6-luna`, a `choice` question and fixed values. Legal choices are `small_attack`, `big_attack`, `heal`, `defend`, and `flee`; exhausted or unavailable actions are omitted. The provider sends only fictional combat stats, not player names, identifiers or photos. Validate the returned choice; unavailable/refused/malformed/timeout falls back to a labelled deterministic small attack. Manual commands remain available.

Demo balance assumptions: small attack uses the existing damage formula; big attack uses 1.5 times attack before defence, capped at three per participant per match. Heal restores 10 HP without exceeding the saved maximum, usable once and only below full HP. Defend halves the next incoming hit. Flee terminates the match with `result: escape` and no winner or reward. Existing `attack` remains accepted as a legacy small attack; missing per-match usage counts are treated as zero.

The server authenticates and reads the current match, checks the player's turn and expected version before selecting. Persist the selection against player + command ID before submitting the existing authoritative move. Exact retries reuse the persisted selection and existing game receipt, avoiding extra selection and double execution; changed payload under the same ID is rejected. Concurrent writes and match rule errors preserve the existing match. Inputs are bounded; API key is server environment only and must not enter source or client. This is a local-only integration, not hosted readiness. Validate rules, authorization, duplicate retry, provider failures, practice and real multiplayer on isolated local MongoDB.

Hosted mode reserves from the shared `POKEPET_HOSTED_OPENAI_CALLS_PER_DAY` daily provider-call quota before contacting Decisions. Missing, invalid, exhausted or unavailable quota uses the labelled deterministic fallback. Concurrent identical calls may reserve more than once before a decision is persisted, but cannot exceed the configured shared cap. This is a call-count limit, not a currency guarantee. Local mode is unaffected.

## Local verification

- Mock provider and pure fallback tests passed. An isolated local MongoDB test passed both face-to-face and practice authorization, legal turns, idempotent retry, provider failure fallback and unchanged opponent data.
- The official Decisions API returned a legal `attack` for synthetic battle state using requested `gpt-6-luna`. A separate live test selected and committed an isolated practice move and retried it without another action.
- Actual Next.js HTTP proof on localhost: two synthetic guest sessions; practice creation; live Decisions auto-move returned `source: decisions`, move `attack`, version 3; same command retried with `duplicate: true`. Test database was isolated and retained; test server stopped. A local process inherited the already authorized avatar-lab key without duplicating secret files. No browser UI, Atlas or hosted production verification is claimed.
- Full root unit suite: 65 passed, one opt-in live-call test skipped. The opt-in test was also run separately and passed. Web typecheck passed.
- Five-action revision: live Decisions selected `big_attack` in an isolated local practice match. Real MongoDB tests verified face-to-face big attack, heal and escape with idempotent retries and opponent readback; practice Auto exercised big attack, heal and flee. The prior 84-pass full suite preceded one additional focused test, which passed separately. UI and hosted acceptance remain outstanding.
