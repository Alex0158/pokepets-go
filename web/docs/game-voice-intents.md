# Game voice and text intents

In progress. A player can speak or type to ask about points, choose a stat upgrade, select a player, begin a Sneak attack or Face-to-face challenge, or report a pet activity. The intent endpoint returns a proposed action only. It does not spend points, start a battle or award a mission. The UI validates the player's intent and delegates actual actions to existing authenticated APIs and idempotent `GameClient` commands.

`POST /api/game-intent` accepts either `{text}` or `{audioBase64,mimeType}` with the current authenticated session. OpenAI transcribes recorded audio and returns `{transcript,intent,stat,targetName,battleMode,view}`. `intent` is one of `points_help`, `open_view`, `upgrade`, `select_player`, `challenge`, `activity_report`, `unknown`; `stat`, `targetName`, `battleMode` and `view` may be null. A view, when present, is one of `map`, `pet`, `battle`, `activity`, `community`. Text is untrusted; the model is not allowed to execute tools. No raw input or transcript is persisted by this endpoint.

Only act on an explicit, unambiguous upgrade or challenge and after UI confirmation. Missing stat/mode/target and multiple matching players require a UI selection; never guess a target. A points question is not an activity report and must never award points. An activity report uses the separate existing scoring endpoint after the player's explicit action. Existing session, ownership, command idempotency and turn validations remain authoritative. Battle navigation must disclose and confirm if entering can trigger default Auto. Audio/text submission must disclose OpenAI processing; input provider failure leaves the game usable. Hosted access defaults off and needs `POKEPET_HOSTED_GAME_INTENT_ENABLED=1` and the shared `POKEPET_HOSTED_OPENAI_CALLS_PER_DAY` Mongo quota; quota failure prevents the provider call.

Verification: focused endpoint/rule tests 6/6; live model classified four synthetic text examples covering help, upgrade, challenge and activity and classified one synthetic recording. The actual authenticated route handler using local Mongo and live OpenAI classified text and synthetic audio while leaving points and progression revision unchanged. At this snapshot the full root suite reported 109 passed and 6 skipped; typecheck passed. Main UI action wiring, microphone capture and hosted access remain separate acceptance gates.

Hosted quota boundary: transcription and classification each reserve one shared UTC-day provider call before contacting OpenAI. A local Mongo test verifies both calls are counted and an exhausted quota blocks a subsequent call. The cap is shared with other hosted AI features and bounds request count, not total currency or per-player abuse. Hosted deployment, origin configuration and live hosted provider requests remain separate validation gates.
