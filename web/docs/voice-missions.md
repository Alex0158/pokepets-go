# Voice activity reports

In progress: an owner records a pet interaction, explicitly sends it for OpenAI transcription and scoring, and receives points. Activity is self-reported, not independently verified. Scoring is bounded to 0–20 integer points per report. This is a demo rule, not a nutrition, safety or veterinary judgment.

The local API accepts JSON `{commandId, audioBase64, mimeType}` or `{commandId, text}` using the existing session cookie. Supported recordings are WebM, MP4 and WAV, up to 1 MiB; text is limited to 4,000 characters. The UI must disclose that the selected input is sent to OpenAI, and offer failure/retry without inventing a reward. Raw audio, typed input and transcripts are not stored in the database. A successful persisted receipt stores a bounded score and input hash; identical retries return the original points without paying again, while changed input with the same ID conflicts. Server-side conditional progression updates serialize with other rewards and upgrades.

Use `gpt-transcribe` for transcription and Responses structured output for scoring. Provider failures before persistence award no points; a lost response or database error may leave the result uncertain. In-flight work is coordinated across processes with a Mongo `voice_jobs` per-command claim and a three-minute lease; the authoritative progression receipt prevents duplicate points even if the lease expires. A retry after expiry can repeat a paid provider call. Claims contain the request digest, lease and status, not raw input. This prototype inherits the existing 64-receipt ceiling, has no distributed abuse/cost limit and is not hosted-ready. Do not present the old fixed mission catalogue as the new voice experience.

`GET /api/voice-mission?commandId=<uuid>` returns `committed`, `pending` for an unexpired Mongo claim, or `not_found`. `not_found` is a point-in-time observation, not proof that an in-flight request cannot later commit. Keep the original ID and bytes for retries; never invent a new ID to recover an uncertain result. Recorded audio is sent to OpenAI when submitted; obtain the player's explicit action and disclose this before submission. Audio and transcript are not persisted by this app; the AI reason and bounded points are kept in the receipt. Provider retention follows the account's OpenAI API policy.

Local verification: synthetic WAV successfully transcribed and scored using the real provider. The actual route handler accepted that WAV, called both OpenAI endpoints, persisted the scored points in isolated local MongoDB, returned the same points on an identical retry, and returned the committed receipt on GET. Focused validation and real Mongo concurrency/failure tests pass. Full root suite with local Mongo replica set and standalone: 57/57 passed, zero skipped. This is direct route-handler proof, not actual browser microphone or deployed HTTP verification. Main UI integration and hosted operation remain pending.

Subsequent isolated Webpack production HTTP test: WAV scored 10 points and exact retry did not re-award; text scored 15 points. An independent Turbopack build returned 200 for authenticated avatar configuration, without calling an image API. A later full root suite reported 79 passed, 1 skipped (live Decisions test).

Latest: the UI's failing WAV was verified to contain zero audio bytes; valid synthetic WAV subsequently succeeded through the real Chrome UI. Empty WAV is now rejected before any paid call. Two isolated service instances against real local Mongo verified shared pending, conflict handling, duplicate receipt recovery and expiry races; score was awarded once even when provider work repeated after an expired lease.
